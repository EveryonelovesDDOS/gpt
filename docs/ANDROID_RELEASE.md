# NEXUS Android Release

NEXUS V12 is configured as a standalone Android application.

## App identity

- App name: **NEXUS**
- Android package: `com.nexus.networkcommandcenter`
- Version: **1.2.0**
- Version code: **12**
- Scheme: `nexus://`
- Light / Dark theme is managed inside NEXUS and persists locally.

## Local Windows APK build

From the repository root:

```cmd
npm ci
npm run android:apk:windows
```

The generated release APK is expected under:

```text
android\app\build\outputs\apk\release\app-release.apk
```

The Android project is generated by Expo Prebuild, so Android Studio / Android SDK and Java 17 must be available.

## GitHub Actions APK

The repository includes `.github/workflows/android-apk.yml`.

Every relevant push to `main` builds an installable release APK and uploads it as the workflow artifact:

```text
NEXUS-v1.2.0-android-apk
└── NEXUS-v1.2.0.apk
```

The artifact is intentionally separate from the Node gateway. The Android application still connects to the local NEXUS gateway and Packet Tracer lab over the configured gateway address.

## Demo Mode

Demo Mode is a presentation simulation. It is designed to demonstrate the complete product story without misrepresenting synthetic evidence as controller evidence.

The eight stages are:

1. Healthy baseline
2. ATTACKER-PC appears
3. Incident Autopilot prepares investigation
4. Digital Twin traces the relationship path
5. Reversible containment plan is prepared
6. Human approval checkpoint
7. Verification workflow
8. Resolution and audit trail

Demo Mode does **not** push IOS commands. It clearly labels its verification result as a presentation simulation.
